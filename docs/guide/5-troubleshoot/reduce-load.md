# 負荷を抑える

> このページは執筆前の骨組みです。設計シートとト書きだけを置き、本文はまだ書いていません(追跡: #219)。

## 設計シート

- 分類: 説明型(Diátaxis: how-to)
- 読み手: だれが / Booth クリエイター、uGUI を避けたいエンジニア、VRChatter。オーバーレイを出すと VR 全体の動きが重くなる、またはオーバーレイが重い / 何を知っている / 画面を組める。計測の道具は持っていない / 読んで何をしたい / 負荷の原因を見つけ、減らしたい
  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: オーバーレイの負荷を、フレームレートの設定、再描画の範囲、更新の頻度の3つの面から抑える手順
- 依頼の解釈: VRChat や GPU のドライバー側の不具合は含めない。FloatSoda のアプリの側で調整できることに絞る
- テーマファイル: how-to
- Why(目的): VR の中で動くため、オーバーレイの負荷が VR 体験全体の快適さに響く。負荷を測って減らせるようにする
- What(目標・結果): 負荷の原因の当たりをつけ、フレームレートの設定と再描画の範囲を調整して、重さが減る
- How(手段): 測る → フレームレートの設定を下げる → 再描画の範囲を絞る → 更新の頻度を減らす、の順
- 要素:
  - 目標のフレームレートは `FloatSodaOptions.TargetFrameRate` で、既定は 60(`src/FloatSoda/FloatSodaOptions.cs`)
  - 作り直し、レイアウト、ペイントは、変わった部分だけ行われる。変更がないフレームは、レイアウトとペイントをスキップする(`AGENTS.md` の「RenderObject Tree」「Widget/Element Tree」)
  - `RepaintBoundary` で囲んだ子は、独立した合成レイヤーに閉じ込められ、再描画が祖先に波及しない(`src/FloatSoda/Widgets/Paint/RepaintBoundary.cs`)
  - `SetState()` を呼ぶ範囲を狭くするほど、作り直す範囲が狭くなる(`src/FloatSoda/Widgets/ComponentWidget.cs`、「状態と作り直し」)
  - `FadeTransition` のように、`SetState()` なしでペイントだけを更新する部品がある(`src/FloatSoda/Widgets/Animation/FadeTransition.cs`)
  - `IntrinsicWidth` と `IntrinsicHeight` はコストが高く、多用しない(`README.md` の「レイアウト系」)
  - `Dpm` と画面のピクセル数が、テクスチャの大きさになる。大きな画面は描画の負荷が増える(`src/FloatSoda/Widgets/WindowWidget.cs`。関係は ※要確認)
  - 複数のウィンドウを同時に出すと、ウィンドウごとにレイアウトと描画の処理が行われる(`src/FloatSoda/FloatSodaApp.cs` の `DrawFrame`)
  - 描画はレンダースレッドで行い、メインスレッドと分かれている(`AGENTS.md` の「Frame Pipeline」)
- 見出し:
  - 最初に、重さの種類を見分ける
  - 手順1: 負荷を測る
  - 手順2: フレームレートの設定を下げる
  - 手順3: 再描画の範囲を絞る
  - 手順4: 更新の頻度を減らす
  - 結果を確かめる
  - それでも直らないとき
- ※要確認:
  - 負荷を測る手段(フレームレートや GPU の使用率を見る道具)。FloatSoda に計測の機能は見当たらない。SteamVR の画面などを使う手順を、実機で確かめて書く
  - `TargetFrameRate` を下げると、オーバーレイの負荷がどの程度下がるか(測って確かめる。確かめられなければ、効果の程度を書かない)
  - `RepaintBoundary` を入れて負荷が下がる具体例(測って確かめる)
  - 画面のピクセル数と負荷の関係(測って確かめる)
  - 定期的な `SetState()`(タイマー)が負荷に与える影響(測って確かめる)

## ト書き

### 最初に、重さの種類を見分ける

- 読み手が持って来るもの: 「重い」という体感
- このページが渡すもの: 見分ける観点(オーバーレイが出ていないときも VR が重いか、オーバーレイの動きだけがカクつくか)と、自分の症状の種類
- 読み手がすること: 症状の種類を決める
- 止まる箇所: オーバーレイを止めても重い場合。FloatSoda の外の話なので、直し方は書かない
- 次へ進む先: 手順1

### 手順1: 負荷を測る

- 読み手が持って来るもの: 重さの種類
- このページが渡すもの: 測る手段と、測る値(フレームレート、GPU の使用率)。何も変えない状態の値の控え方
- 読み手がすること: 変える前の値を控える
- できた?: 変える前の値が手元にある
- 次へ進む先: 手順2
- 【未決】測る手段をこのページで書くか。FloatSoda 側に計測の機能がないため、外部の道具の手順になる

### 手順2: フレームレートの設定を下げる

- 読み手が持って来るもの: 控えた値
- このページが渡すもの: `TargetFrameRate` の指定方法と、既定の 60
- 読み手がすること: 値を下げて起動し、同じ操作で測り直す
- できた?: 値の変化が数字で見える
- 次へ進む先: 手順3

### 手順3: 再描画の範囲を絞る

- 読み手が持って来るもの: 手順2のあとの値
- このページが渡すもの: `RepaintBoundary` で囲む位置の選び方と、`SetState()` を呼ぶ `State` を小さく分ける方法
- 読み手がすること: 頻繁に変わる部分を `RepaintBoundary` で囲む
- できた?: 変わらない部分が再描画されない(測り直した値で確かめる)
- 次へ進む先: 手順4

### 手順4: 更新の頻度を減らす

- 読み手が持って来るもの: タイマーなどで更新している画面
- このページが渡すもの: 更新の間隔を長くする、`FadeTransition` のように `SetState()` なしの部品に替える、`IntrinsicWidth` / `IntrinsicHeight` を避ける、の3つ
- 読み手がすること: 該当するものを直す
- できた?: 測り直した値が下がる
- 次へ進む先: 「結果を確かめる」

### 結果を確かめる

- 読み手が持って来るもの: 直したコード
- このページが渡すもの: 控えた値との比較の仕方
- 読み手がすること: 値を比べる
- 次へ進む先: 「それでも直らないとき」

### それでも直らないとき

- 読み手が持って来るもの: 直らない重さ
- このページが渡すもの: ガイドの「5. 困ったとき」の入口ページの「どこでだれに聞くか」へのリンク。聞くときに添える情報(測った値、ウィンドウの数と種類、画面の大きさ)
- 読み手がすること: 聞く
- 止まる箇所: なし。ここでページは終わる
