# レイアウトの考え方

## 設計シート

- 分類: 説明型(Diátaxis: explanation)
- 読み手: だれが / Booth クリエイター(uGUI の経験者)、uGUI を避けたいエンジニア、AI に頼む VRChatter。画面が思った大きさや位置にならない / 何を知っている / uGUI の `RectTransform` とアンカーの考え方。Flutter は知らない / 読んで何をしたい / 大きさが決まる仕組みを知り、思った大きさにならない理由を自分で見つけられるようになりたい
  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: 親が制約を渡し、子が大きさを決めて返す、というレイアウトの規則
- 依頼の解釈: 個々のウィジェットの全プロパティの説明(リファレンス)は含めない。考え方と、思った大きさにならない典型の原因に絞る
- テーマファイル: explanation
- Why(目的): 大きさが「親の制約」と「子の希望」で決まると知らないと、`SizedBox` が効かない、中央に寄らないなどの現象が説明できない
- What(目標・結果): 「制約が下り、サイズが上る」の規則と、`Align`・`SizedBox`・`Expanded`・`Flex` が規則にどう関わるかが分かる
- How(手段): 規則 → 規則から説明できる典型の現象 → ウィンドウの大きさとの関係、の順に説明する
- 要素:
  - レイアウトは「制約が親から子へ下り、サイズが子から親へ上る」規則で行われる(`README.md` のレンダリングライフサイクル図の注記、`AGENTS.md` の「RenderObject Tree」)
  - 制約は `BoxConstraints` で、最小と最大の幅・高さを持つ(`src/FloatSoda/Geometrics/BoxConstraints.cs`)
  - `SizedBox` は子へ固定の制約を渡す(`README.md` の「レイアウト系」)。ただし親の制約が厳しい(tight)と、親の制約が優先される(Flutter の規則。FloatSoda での確認は ※要確認)
  - `Align` / `Center` は、子を `Alignment` で配置する。親いっぱいに広がる(`README.md` の「レイアウト系」。広がる条件は ※要確認)
  - `Flex` / `Row` / `Column` は、余りの領域を `Expanded` / `Flexible` / `Spacer` で比率分配する(`README.md` の「レイアウト系」)
  - `Stack` は子を重ね、`Positioned` で絶対配置する(`README.md` の「レイアウト系」)
  - `ConstrainedBox`、`LimitedBox`、`ConstraintsTransformBox`、`UnconstrainedBox` は、子へ渡す制約を加工する(`README.md` の「レイアウト系」)
  - `Size` を指定したウィンドウは、その大きさで子をレイアウトする(Tight)。省略したウィンドウは、子のレイアウト結果にウィンドウが追従する(Loosen)(`src/FloatSoda/Widgets/WindowWidget.cs`)
  - 省略したウィンドウは、起動後に中身の大きさが変わっても、SteamVR 上の表示が最初の大きさのままになる(`CHANGELOG.md`、追跡: #285)
  - レイアウトの規則は Flutter と同じで、差異があるときは Flutter との違いとして記録される(`AGENTS.md` の「Repository Conventions」、`CONTRIBUTING.md`)
  - 長さの単位はピクセルで、実寸は `Dpm` で決まる(`src/FloatSoda/Widgets/WindowWidget.cs`)
- 見出し:
  - 大きさは、親の制約と子の希望で決まる
  - 制約は上から下へ、サイズは下から上へ流れる
  - SizedBox を指定したのに、大きさが変わらない
  - Align で包んだら、中央に寄る
  - Row と Column で、余りの領域を分ける
  - ウィンドウの大きさは、Size を指定するかで変わる
  - Flutter を知っている人へ
- ※要確認:
  - 親の制約が tight のとき、`SizedBox` の幅と高さが無視される動き(Flutter と同じか、サンプル `FloatSoda.Samples.SizedBox` を読み、実行して確かめる)
  - `Align` が、制約が無限のときに子のサイズにフィットする動き(`FloatSoda.Samples.Align` を読んで確かめる)
  - `Container` が `Padding` をまだ合成しないことによる、余白の指定の差(`AGENTS.md` の「Widget/Element Tree」、実コードで確かめる)
  - 図に使う例が、サンプルの実行結果と一致すること(画像にして確かめる)
