# HMD を被らずに確かめる

  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: `DesktopWindow` でデスクトップの窓に出す方法と、`FloatSoda.Testing` で画像にして比べる方法で、HMD を被らずに確かめる手順
- 依頼の解釈: 「HMD を被らずに」は、HMD を頭に付けずにという意味に決めた。HMD の接続と SteamVR の起動は、どちらの方法でも要る
- テーマファイル: how-to
- Why(目的): 見た目や動きの確認のたびに HMD を被る回数を減らす
- What(目標・結果): デスクトップの窓に画面が出る。または、ウィジェットを画像ファイルに書き出して見られる
- How(手段): 方法1(窓に出す)と方法2(画像にする)を、手順を分けて書く。どちらを使うかの選び方は、ページの冒頭に置く
- 要素:
  - `DesktopWindow` を `CreateWindow` に渡すと、デスクトップに可視の窓として出る(`src/FloatSoda/Widgets/WindowWidget.cs`、`src/FloatSoda.Engine/DesktopWindow.cs`)
  - サンプルは `--desktop` の引数で、`DashboardWindow` と `DesktopWindow` を切り替えている(`samples/FloatSoda.Samples.GestureDetector/Program.cs`)
  - `--desktop` でも HMD の接続と SteamVR の起動は要る。HMD 未接続では `Init_HmdNotFound` で起動に失敗する(`CONTRIBUTING.md`、追跡: #140)
  - デスクトップの窓ではマウスで操作できる(`src/FloatSoda.Engine/GLFWRawPointerSource.cs`)
  - デスクトップで動いても、ダッシュボードで動く証明にはならない。ウィンドウ種別ごとに入力の経路が違う(`CONTRIBUTING.md`、追跡: #182)
  - `WidgetBitmapRenderer.Render(widget, imageSize)` は、ウィジェットを画像(`SKBitmap`)にする。SteamVR は要らない(`src/FloatSoda.Testing/WidgetBitmapRenderer.cs`)
  - `WidgetBitmapRenderer` はビルド・レイアウト・ペイントを1回だけ実行する。非同期で読み込む画像は、描画の前に解決しておく(`src/FloatSoda.Testing/WidgetBitmapRenderer.cs` の remarks)
  - `FloatSoda.Samples.PaintingSample` は、ツリーの描画結果を PNG に書き出す(`samples/FloatSoda.Samples.PaintingSample/Program.cs`)
  - 画像を比べる手順(期待する画像との比較)は、リポジトリの `tests/` に画素を調べるテストがある。利用者が使える形かは ※要確認(`CONTRIBUTING.md`)

  - 方法2: 画像にして比べる
  - 結果を確かめる

- ※要確認:
  - `FloatSoda.Testing` が NuGet で配布されているか(`src/FloatSoda.Testing/FloatSoda.Testing.csproj` に `PackageId` はある。公開の有無は NuGet で確かめる)

  - HMD を接続していない PC で `--desktop` が動かない状況の回避策。今はないと読めるが、`FloatSodaApp.Initialize()` を読み直して確かめる(追跡: #140)

## ト書き

### どちらの方法を使うか

- 読み手が持って来るもの: 「HMD を被る手間を減らしたい」という目的
- このページが渡すもの: 2つの方法の違い(窓に出すと目で見られる、画像にすると自動で比べられる)と、どちらも HMD の接続と SteamVR の起動は要る方法と要らない方法があること
- 読み手がすること: 自分の目的に合う方法を選ぶ
- 次へ進む先: 「前提条件」
- 【未決】2つの方法をこのページに置くか、2ページに分けるか。分けると、タイトルが「窓に出す」と「画像で比べる」になる

### 前提条件

- 読み手が持って来るもの: 自分のプロジェクト
- このページが渡すもの: 要るもの。方法1は SteamVR の起動と HMD の接続(追跡: #140)。方法2は SteamVR も HMD も要らない
- 読み手がすること: 確かめる
- 次へ進む先: 方法1または方法2

### 方法1: デスクトップの窓に出す

- 読み手が持って来るもの: `DashboardWindow` で出している起動のコード
- このページが渡すもの: `DesktopWindow` への差し替え方と、`--desktop` の引数で切り替えるサンプルの形
- 読み手がすること: 窓の種類を差し替えて起動する
- できた?: デスクトップに窓が出て、マウスで操作できる
- 次へ進む先: 「結果を確かめる」
- 止まる箇所: デスクトップで動いても、ダッシュボードで動く証明にならないこと(追跡: #182)。ボタンを押せる画面は、最後に HMD で確かめる

### 方法2: 画像にして比べる

- 読み手が持って来るもの: テストしたいウィジェット
- このページが渡すもの: `WidgetBitmapRenderer.Render` の呼び方と、画像を保存して見る方法。非同期で読み込む画像を使うときの注意
- 読み手がすること: ウィジェットを画像にして、保存した画像を開く
- できた?: PNG ファイルが保存され、画面と同じ見た目になっている
- 次へ進む先: 「結果を確かめる」
- 【未決】期待する画像との比較を、このページで書くか。書くなら、比較の基準(画素の一致か、許容する差か)を決める必要がある

### 結果を確かめる

- 読み手が持って来るもの: 窓または画像
- このページが渡すもの: 見る観点(配置、色、文字)と、HMD で最後に確かめる項目
- 読み手がすること: 目で確かめる
- 次へ進む先: 「見た目を整える」「ボタンやトグルを組み立てる」

### うまくいかないとき

- 読み手が持って来るもの: 窓が出ない、または起動で例外が出る
- このページが渡すもの: ガイドの「5. 困ったとき」の「エラーを読んで直す」へのリンク
- 読み手がすること: リンク先で切り分ける
- 止まる箇所: なし
