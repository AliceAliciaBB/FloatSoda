# オーバーレイの種類と選び方

> このページは執筆前の骨組みです。設計シートとト書きだけを置き、本文はまだ書いていません(追跡: #219)。

## 設計シート

- 分類: 説明型(Diátaxis: explanation)
- 読み手: だれが / VRChatter、Booth クリエイター、uGUI を避けたいエンジニア。自分の物をどこに出すかを決める前 / 何を知っている / SteamVR のダッシュボードを開いたことがある / 読んで何をしたい / ダッシュボード、空間に固定、手首などに追従の違いを知り、自分の物に合う種類を選びたい
  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: `DashboardWindow`、`WorldSpaceWindow`、`DeviceTrackedWindow` の出る場所の違いと、入力が届くかの違い
- 依頼の解釈: 「通知のときだけ出して消す」(出し入れ)は、機能がないため含めない(解除の条件は Phase 4。追跡: #219)。開発用の `DesktopWindow` は「HMD を被らずに確かめる」で扱う
- テーマファイル: explanation
- Why(目的): 種類を選び間違えると、ボタンが押せない物ができるため、作る前に選ぶ基準を持てるようにする
- What(目標・結果): 3種類のオーバーレイの出る場所、入力の届き方、サイズの決まり方の違いが分かり、自分の物に合う種類を選べる
- How(手段): 3種類を同じ観点(出る場所、操作できるか、サイズ、位置の指定)で比べ、用途ごとの選び方で終える
- 要素:
  - `DashboardWindow` は SteamVR ダッシュボードに出る。表示サイズは SteamVR が管理するため、`Dpm` が効かない場合がある(`src/FloatSoda/Widgets/WindowWidget.cs`)
  - `WorldSpaceWindow` はワールド座標に固定される。`Position` は床中央が原点で、前方が -Z。既定は前方 1m、高さ 1m(`src/FloatSoda/Widgets/WindowWidget.cs`)
  - `DeviceTrackedWindow` は `Target`(左右のコントローラーや HMD)に追従し、`Offset` と `Rotation` で位置を決める(`src/FloatSoda/Widgets/WindowWidget.cs`)
  - ポインタ座標はダッシュボードにだけ届く。`WorldSpaceWindow` と `DeviceTrackedWindow` は表示専用(`README.md` の「開発ステータス」、追跡: #182)
  - `Dpm` は物理密度(dots per meter)で、既定は 4000。幅 1000px のウィジェットは実寸 25cm になる(`src/FloatSoda/Widgets/WindowWidget.cs`)
  - `Size` を指定しないウィンドウは、中身のレイアウト結果にサイズが追従する。ただし起動後に中身の大きさが変わると、SteamVR 上の表示は最初の大きさのままになる(`CHANGELOG.md`、追跡: #285)
  - 1つのアプリが複数のウィンドウを同時に作れる(`samples/FloatSoda.Samples.OverlayApp/Program.cs`)
  - ウィンドウの `Title` が、ダッシュボードのタブ名になる(`src/FloatSoda/Widgets/WindowWidget.cs`)
  - 用途の例: 操作するパネル → ダッシュボード。表示だけの時計 → 空間に固定、またはコントローラーに追従(`samples/FloatSoda.Samples.OverlayApp/Program.cs` の時計の例)
- 見出し:
  - オーバーレイは3種類あり、出る場所と入力の届き方が違う
  - ダッシュボード: 操作できる
  - 空間に固定: 表示専用
  - 手首などに追従: 表示専用
  - 大きさの決まり方
  - 自分の物に合う種類の選び方
- ※要確認:
  - ダッシュボードのオーバーレイのサムネイルやアイコンを指定する手段の有無(`src/FloatSoda/Widgets/WindowWidget.cs` には見当たらない)
  - `DeviceTrackedWindow` の `Offset` の座標系の向き(コントローラーのどの軸か。HMD で確かめる)
  - 3種類を同時に出したときの負荷(測って確かめる。「負荷を抑える」と重なる)

## ト書き

### オーバーレイは3種類あり、出る場所と入力の届き方が違う

- 読み手が持って来るもの: 「どこに出すか」という問い
- このページが渡すもの: 3種類の違いを1枚にまとめた表(出る場所、操作できるか、位置の決め方)と、冒頭の結論(操作が要るならダッシュボード)
- 読み手がすること: 表を見て、候補を絞る
- 次へ進む先: 次の節

### ダッシュボード: 操作できる

- 読み手が持って来るもの: 絞った候補
- このページが渡すもの: `DashboardWindow` の出る場所、`Title` がタブ名になること、操作できる理由
- 読み手がすること: 操作する物はこの種類と決める
- 次へ進む先: 次の節

### 空間に固定: 表示専用

- 読み手が持って来るもの: 前の節
- このページが渡すもの: `WorldSpaceWindow` の座標系(床中央が原点)、既定位置、表示専用の制約(追跡: #182)
- 読み手がすること: 表示だけでよい物はこの種類を検討する
- 次へ進む先: 次の節

### 手首などに追従: 表示専用

- 読み手が持って来るもの: 前の節
- このページが渡すもの: `DeviceTrackedWindow` の `Target`、`Offset`、`Rotation`、表示専用の制約(追跡: #182)
- 読み手がすること: 手元に出したい物はこの種類を検討する
- 次へ進む先: 次の節

### 大きさの決まり方

- 読み手が持って来るもの: 3種類の候補
- このページが渡すもの: `Dpm` と `Size` の関係。`Size` を省略したときの動きと既知の問題(追跡: #285)
- 読み手がすること: 自分の物の大きさの決め方をつかむ
- 次へ進む先: 次の節
