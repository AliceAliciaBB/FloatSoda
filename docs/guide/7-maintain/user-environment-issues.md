# 利用者の環境で動かないとき

> このページは執筆前の骨組みです。設計シートとト書きだけを置き、本文はまだ書いていません(追跡: #219)。

## 設計シート

- 分類: 説明型(Diátaxis: how-to)
- 読み手: だれが / Booth クリエイター、VRChatter。自分の PC では動くが、購入者や友人の PC で動かないと報告を受けた / 何を知っている / 自分の PC での動かし方。相手の環境は見えない / 読んで何をしたい / 相手の環境の情報を集め、自分の側の問題か、相手の環境の問題か、FloatSoda の問題かを切り分けたい
  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: 相手の環境の情報を集めて、動かない原因を切り分ける手順
- 依頼の解釈: 自分の PC で動かない場合は含めない(「エラーを読んで直す」を使う)。コントリビューター向けの「不具合を切り分けて報告する」と同じ形で、集める情報をそろえる
- テーマファイル: how-to
- Why(目的): 相手の環境が見えない状態でも、集める情報が決まっていれば、切り分けが進む。FloatSoda の不具合なら、その情報をそのまま Issue にできる
- What(目標・結果): 相手の環境の情報が1つの形でそろい、原因が「自分のコード」「相手の環境」「FloatSoda」のどれかに絞れる
- How(手段): 相手に集めてもらう情報を決める → 症状ごとに切り分ける → FloatSoda の不具合なら Issue にする、の順
- 要素:
  - 集める情報は、コントリビューター向けの動作検証の報告(落ちたか落ちなかったかと環境)と同じ形にする(docs 再編の決定、2026-10-16。コントリビューター向けの該当ページは追跡: #219)
  - 環境の情報として、OS、GPU、HMD、SteamVR の版、FloatSoda の版、窓の種類が要る(`CONTRIBUTING.md` の実機巡回の結果ファイル名 `<hmd>-<gpu>-<platform>-<mode>-<yyyy-MM-dd>`)
  - HMD 未接続では、デスクトップの窓でも `Init_HmdNotFound` で起動に失敗する(`CONTRIBUTING.md`、追跡: #140)
  - 起動のログには、OpenVR の初期化の失敗、アプリの識別の失敗、入力の初期化の失敗が出る(`src/FloatSoda/FloatSodaApp.cs`)
  - ダッシュボード以外のオーバーレイでは、ボタンが反応しない(`README.md`、追跡: #182)
  - `Size` を指定しないウィンドウは、起動後に中身の大きさが変わると、表示が更新されない(`CHANGELOG.md`、追跡: #285)
  - 不具合の報告は、Issue のテンプレートを使う(`.github/ISSUE_TEMPLATE/bug_report.yml`、`CONTRIBUTING.md`)
  - 切り分けの対象は、相手の環境(SteamVR 未起動、HMD 未接続、ランタイム不足)、配布物の不足(ネイティブライブラリ)、自分のコード、FloatSoda の不具合
- 見出し:
  - この手順でできること
  - 前提条件
  - 手順1: 相手に環境の情報を集めてもらう
  - 手順2: 自分の PC で再現するかを確かめる
  - 手順3: 症状から原因を絞る
  - 手順4: FloatSoda の不具合なら Issue にする
  - 結果を確かめる
  - うまくいかないとき
- ※要確認:
  - Issue のテンプレート(`bug_report.yml`)の項目と、集める環境の情報が一致しているか(`.github/ISSUE_TEMPLATE/bug_report.yml` を読んで確かめる)
  - 相手に環境の情報を集めてもらう手段(ログの場所、SteamVR の版の確認方法)。ログの出力先は、ホストの設定による(「Generic Host の仕組みを使う」と合わせて決める)
  - コントリビューター向けの「不具合を切り分けて報告する」ページのパスと見出し(別担当のページ。リンク先が決まってから、形を揃える)
  - 相手の環境でだけ起こる代表的な原因の一覧(実際の報告から集める。今は報告がないため、一覧は作らず、切り分けの順番だけを書く)

## ト書き

### この手順でできること

- 読み手が持って来るもの: 「購入者の PC で動かない」という報告
- このページが渡すもの: 完成の状態(原因が3つのどれかに絞れる)と、手順の数
- 読み手がすること: 目的を確かめる
- 次へ進む先: 「前提条件」

### 前提条件

- 読み手が持って来るもの: 動かないという報告と、相手とやり取りできる手段
- このページが渡すもの: 要るもの(自分の PC では動くこと、配布物の版が分かっていること)
- 読み手がすること: 確かめる
- 次へ進む先: 手順1

### 手順1: 相手に環境の情報を集めてもらう

- 読み手が持って来るもの: 相手との連絡手段
- このページが渡すもの: 相手に聞く項目(OS、GPU、HMD、SteamVR の版、配布物の版、窓の種類、出たメッセージ)を、そのまま送れる形で
- 読み手がすること: 項目を相手に送り、返事をもらう
- できた?: 項目が埋まった返事がある
- 次へ進む先: 手順2

### 手順2: 自分の PC で再現するかを確かめる

- 読み手が持って来るもの: 相手の環境の情報
- このページが渡すもの: 自分の PC で、相手と同じ版・同じ窓の種類で動かす手順
- 読み手がすること: 再現するかを確かめる
- できた?: 再現した、または再現しなかったと言える
- 次へ進む先: 手順3

### 手順3: 症状から原因を絞る

- 読み手が持って来るもの: 再現の有無と環境の情報
- このページが渡すもの: 症状ごとの絞り方(起動しない → SteamVR・HMD・配布物の不足、押せない → 窓の種類、表示の大きさが違う → `Size`)と、「エラーを読んで直す」「反応しないときに切り分ける」へのリンク
- 読み手がすること: 原因を3つのどれかに絞る
- できた?: 原因が絞れた
- 止まる箇所: 原因が FloatSoda にあるか分からない場合。手順4へ進み、情報を添えて Issue にする
- 次へ進む先: 手順4

### 手順4: FloatSoda の不具合なら Issue にする

- 読み手が持って来るもの: 絞った原因と環境の情報
- このページが渡すもの: Issue の立て方と、添える情報(手順1の項目、再現するコード、再現の有無)。コントリビューター向けの「不具合を切り分けて報告する」へのリンク
- 読み手がすること: Issue を立てる
- 止まる箇所: 相手の環境の問題だった場合は、Issue にせず、相手に直し方を伝える
- 次へ進む先: 「結果を確かめる」

### 結果を確かめる

- 読み手が持って来るもの: 直した版または相手の環境の対処
- このページが渡すもの: 相手の PC で動いたことを確かめる観点
- 読み手がすること: 相手に動いたかを聞く
- 次へ進む先: 版を届けるときは「exe にして配る」の手順4

### うまくいかないとき

- 読み手が持って来るもの: 原因が絞れない
- このページが渡すもの: ガイドの「5. 困ったとき」の入口ページの「どこでだれに聞くか」へのリンク
- 読み手がすること: 聞く
- 止まる箇所: なし
