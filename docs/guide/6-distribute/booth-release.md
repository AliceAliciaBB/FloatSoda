# Booth で売る準備

## この手順でできること

オーバーレイを Booth で売るときに、同梱するものと商品ページに書く動作環境をそろえます。終わると、購入者が説明書だけで起動できる状態になり、動かないという問い合わせを減らせます。手順は 4 つです。

1. 同梱するものを決める
2. 購入者向けの説明書を書く
3. 動作環境を書く
4. 配布物を確かめる

Booth の出品画面の操作は、このページでは扱いません。Booth の公式の資料を参照してください。

## 前提条件

次の 2 つを済ませてください。

- [exe にして配る](publish-exe.md) の手順 1 から 3 を終えていること
- zip にまとめた配布物があること

## 手順1: 同梱するものを決める

zip に入れるものは、次の 3 種類です。

| 同梱するもの | 要る理由 |
| :-- | :-- |
| `.exe` と必要なファイル | 購入者の PC で動かすため。`dotnet publish` の出力をそのまま入れる |
| 説明書(テキストファイル) | 起動の順番と操作を伝え、問い合わせを減らすため |
| ライセンス表記 | 再配布するライブラリのライセンス条件を守るため |

ライセンス表記は、FloatSoda のリポジトリにある [LICENSE](../../../LICENSE) と [THIRD_PARTY_NOTICES.md](../../../THIRD_PARTY_NOTICES.md) を入れます。FloatSoda のライセンスは MIT で、MIT ライセンスは、配布物に著作権表示と許諾表示を含めることを条件にしています。`THIRD_PARTY_NOTICES.md` には、Flutter、OpenVR SDK、OVRSharp のライセンスの全文が載っています。

配布物に含まれる、ほかのライブラリ(SkiaSharp など)のライセンスは、各ライブラリの配布元で確かめ、条件が求める表示や文書を同梱してください。`LICENSE` と `THIRD_PARTY_NOTICES.md` だけで足りるとは限りません。法的な判断は、このページでは行いません。

<!-- ※要確認: 配布物にライセンス表記を含める必要があるかどうかは、各ライブラリのライセンス条件で確かめていない。THIRD_PARTY_NOTICES.md の内容を配布物に含める要否も同様。MIT ライセンスのソフトウェアを Booth で販売できるかは、LICENSE の文面を読んだ範囲では制限が見当たらないが、法的な判断はしていない -->

**できた?** 同梱物の一覧が手元にある。

## 手順2: 購入者向けの説明書を書く

説明書は、初めて見る人が、説明書だけで起動できるように書きます。書く項目は次のとおりです。

1. 動作環境(SteamVR が要ること、OS、HMD)
2. 起動の順番(SteamVR を先に起動し、そのあとに `.exe` を動かす)
3. オーバーレイの出し方(商品で使うウィンドウの種類に合わせた表示手順。ダッシュボードなら、ダッシュボードを開いてタブを選ぶ)
4. 操作の方法(ポインタで押す操作に対応するのが、ダッシュボードのオーバーレイだけであること)
5. 動かないときの連絡先
6. 動作確認した版(商品の版、同梱した FloatSoda の版、動作確認した SteamVR の版)

ポインタで押す操作に対応しているのは、ダッシュボードのオーバーレイだけです。`WorldSpaceWindow` と `DeviceTrackedWindow` はポインタで押せないので、これらを使う商品では、「ポインタでは押せない」と書きます(追跡: #182)。コントローラーのボタンで操作できる商品なら、その操作方法も書きます。

FloatSoda は Alpha の段階で、API が変わることがあります。動作確認した版を書いておくと、購入者が、問い合わせのときに版を伝えられます。

SteamVR の起動と同時にオーバーレイを自動で起動させる設定を商品に含める場合は、[SteamVR と一緒に起動する](launch-with-steamvr.md) の手順が要ります。マニフェストの自動生成は検討中で、今は手動です。

説明書の雛形は、このページには載せません。項目の一覧が、このページでの正です。

**できた?** 初めて見る人が、説明書だけで起動できる。

## 手順3: 動作環境を書く

商品ページには、購入者の PC に要るものを書きます。動作環境の一覧は、リファレンスの [動作環境](../../reference/requirements.md) と共有しています。商品ページには、そこに載っている実行する PC の項目を写し、商品独自の条件を加えます。実際に確かめた環境と、動作を保証しない環境は分けて書きます。

書く項目は次の 3 点です。

- SteamVR が要ることと、起動してから使うことを書くこと
- ポインタで押せるオーバーレイの種類を書くこと(手順 2 の 4 と同じ内容にする)
- .NET のランタイムが要るかどうかを書くこと(ランタイムを同梱した配布物なら、要らないと書く)

**できた?** 商品ページに動作環境が書かれている。

## 手順4: 配布物を確かめる

出品する前に、別の PC で、説明書だけを見て起動します。確かめる観点は次のとおりです。

- zip を展開して、`.exe` を起動できる
- 説明書の手順どおりに、オーバーレイが出る
- 説明書にある操作ができる

自分の PC の開発環境が残っていると、足りないファイルに気づけません。配布先と同じ条件の別の PC で確かめてください。ランタイムを同梱した配布物なら、.NET の SDK もランタイムも入っていない PC で起動できることも確かめます。ユーザーアカウントを分けただけでは、PC に入った SDK やランタイムは残ります。

**できた?** 説明書の手順どおりにオーバーレイが出る。

## 結果を確かめる

出品の前に、次の 4 点を点検します。

- 同梱物の一覧が、zip の中身と一致している
- 説明書に、手順 2 で決めた項目がすべて書かれている
- 商品ページの動作環境が、説明書と同じ内容になっている
- 別の PC での起動を確かめた

出品後に「動かない」という報告を受けたら、[利用者の環境で動かないとき](../7-maintain/user-environment-issues.md) で切り分けます。

## うまくいかないとき

配布物が別の PC で動かないときは、[exe にして配る](publish-exe.md) と [利用者の環境で動かないとき](../7-maintain/user-environment-issues.md) を読んで、切り分けます。
