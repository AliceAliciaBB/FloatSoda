# exe にして配る

> このページは執筆前の骨組みです。設計シートとト書きだけを置き、本文はまだ書いていません(追跡: #219)。

## 設計シート

- 分類: 説明型(Diátaxis: how-to)
- 読み手: だれが / Booth クリエイター、VRChatter。自分の PC で動くオーバーレイができた / 何を知っている / `dotnet run` で動かせる。配布用にビルドした経験はないか、AI に頼む / 読んで何をしたい / 他人の PC で動く exe にして渡し、直した版も同じ手順で届けたい
  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: オーバーレイを配布用の exe にして渡し、修正版を届けるまでの手順
- 依頼の解釈: 「配る」は、zip などのファイルとして渡すことに決めた。Booth の商品ページの作り方は、「Booth で売る準備」で扱う
- テーマファイル: how-to
- Why(目的): 開発環境のない相手の PC でも、オーバーレイを動かせるようにする
- What(目標・結果): .NET の SDK を入れていない PC で、フォルダーの exe を起動するとオーバーレイが出る。修正版も同じ手順で作り直して届けられる
- How(手段): 公開用の設定でビルドする → 開発環境のない環境で動かして確かめる → 渡す → 更新版を届ける、の順
- 要素:
  - FloatSoda のサンプルは `OutputType` が `Exe` のコンソールアプリで、通常の .NET アプリとして配布できる(`samples/FloatSoda.Samples.GettingStarted/FloatSoda.Samples.GettingStarted.csproj`、前の docs の `TargetUsers`。※要確認)
  - 動作に SteamVR と OpenVR のランタイムが要る(`CONTRIBUTING.md`、前の docs の GettingStarted)
  - 配布先の PC に .NET 10 のランタイムが要るかどうかは、`dotnet publish` の設定(自己完結か否か)で決まる(.NET の公式資料。※要確認)
  - 配布物には、ネイティブライブラリ(OpenVR の `openvr_api.dll` など)を含める必要がある(`src/FloatSoda.OVR/openvr_api.dll`。同梱のされ方は ※要確認)
  - マニフェストファイルの自動生成は検討中で、今は手動(`README.md` の「開発ステータス」、追跡: #219)
  - `AppKey` はアプリごとに固有の値にする(`src/FloatSoda/FloatSodaOptions.cs`)
  - 修正版を届けるときの確かめ事: 同じ `AppKey` で動くこと、設定ファイルが上書きされないこと(※要確認)
  - 配布先で動かないときの切り分けは、「利用者の環境で動かないとき」で扱う
- 見出し:
  - この手順でできること
  - 前提条件
  - 手順1: 配布用にビルドする
  - 手順2: 開発環境のない PC で動かして確かめる
  - 手順3: 渡す
  - 手順4: 修正版を届ける
  - 結果を確かめる
  - うまくいかないとき
- ※要確認:
  - 一次情報が足りない。FloatSoda の側に、公開(`dotnet publish`)の設定や手順を書いた資料がない。`dotnet publish` で動く exe が作れるかを、実際にビルドして動かして確かめる必要がある
  - 自己完結の公開(ランタイム同梱)と、ランタイム依存の公開のどちらを手順に選ぶか(動かして比べる。.NET の公式資料を読む)
  - ネイティブライブラリ(`openvr_api.dll`、SkiaSharp、GLFW)が公開フォルダーに入ること(実際に公開して確かめる)
  - 単一ファイルの公開が使えるか(ネイティブライブラリがあるため。動かして確かめる)
  - 開発環境のない PC で、SteamVR を先に起動していないと起動に失敗すること(`src/FloatSoda/FloatSodaApp.cs`、実機で確かめる)
  - 更新版を届けるときの、利用者に求める操作(上書き、削除の要否)と、設定ファイルの扱い

## ト書き

### この手順でできること

- 読み手が持って来るもの: 「他人の PC で動かしたい」という目的
- このページが渡すもの: 完成の状態(フォルダーを渡すと、相手の PC でオーバーレイが出る)と、手順の数
- 読み手がすること: 目的を確かめる
- 次へ進む先: 「前提条件」

### 前提条件

- 読み手が持って来るもの: 自分の PC で動くプロジェクト
- このページが渡すもの: 要るもの(.NET 10 の SDK、動作確認済みであること、配布先に SteamVR があること)。配布先の動作環境の一覧は、リファレンスの「動作環境」へのリンクで渡す
- 読み手がすること: 確かめる
- 次へ進む先: 手順1

### 手順1: 配布用にビルドする

- 読み手が持って来るもの: プロジェクト
- このページが渡すもの: `dotnet publish` のコマンド1つと、出力先のフォルダー
- 読み手がすること: コマンドを実行する
- できた?: 出力先のフォルダーに exe と必要なファイルが並ぶ
- 次へ進む先: 手順2
- 【未決】自己完結の公開とランタイム依存の公開の、どちらを手順にするか。選ばなかったほうは、選択肢として添えるか省くか

### 手順2: 開発環境のない PC で動かして確かめる

- 読み手が持って来るもの: 公開したフォルダー
- このページが渡すもの: 確かめる環境の条件(SDK なし、SteamVR あり)と、起動の手順
- 読み手がすること: 別の PC、またはまっさらなユーザーアカウントで起動する
- できた?: ダッシュボードにオーバーレイが出る
- 次へ進む先: 手順3
- 止まる箇所: 動かないとき。直し方は書かず、「利用者の環境で動かないとき」へ送る

### 手順3: 渡す

- 読み手が持って来るもの: 動作確認したフォルダー
- このページが渡すもの: zip にまとめる手順と、同梱する説明(起動前に SteamVR を起動することなど)
- 読み手がすること: zip にする
- できた?: 別の場所で展開しても動く
- 次へ進む先: 手順4

### 手順4: 修正版を届ける

- 読み手が持って来るもの: 直したコード
- このページが渡すもの: 手順1から3をもう一度行うこと、版の付け方、利用者に求める操作
- 読み手がすること: 版を上げて作り直し、渡す
- できた?: 更新した版を展開したとき、前の版と同じように動く
- 次へ進む先: 「結果を確かめる」

### 結果を確かめる

- 読み手が持って来るもの: 渡した版
- このページが渡すもの: 受け取った人が確かめる観点
- 読み手がすること: 受け取った人に確かめてもらう
- 次へ進む先: 「Booth で売る準備」「SteamVR と一緒に起動する」

### うまくいかないとき

- 読み手が持って来るもの: 公開に失敗する、または相手の PC で動かない
- このページが渡すもの: ガイドの「7. メンテナンスする」の「利用者の環境で動かないとき」へのリンク
- 読み手がすること: リンク先で切り分ける
- 止まる箇所: なし
