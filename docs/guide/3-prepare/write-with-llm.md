# AI に FloatSoda を書かせる

この手順で、AI に FloatSoda の資料を渡してコードを書かせ、出来上がったコードで SteamVR のダッシュボードにオーバーレイを出し、FloatSoda で起きやすい食い違いを点検できます。コードを読めなくても進められます。手順は5つです。

AI は、Flutter の知識で書いた「動かないコード」を出すことがあります。FloatSoda は Flutter に似ていますが、名前や引数が違う部品があり、まだない部品もあります。資料を渡すこと、ビルドと実行で確かめること、よくある食い違いを検索で点検することが、この事故を減らします。

始める前に、[開発環境を用意する](set-up-environment.md)を済ませて、FloatSoda を足したコンソールアプリを用意してください。この手順では、そのアプリの `Program.cs` を書き換えます。

## 手順1: AI に資料を渡す

> 【未決】この節は判断が要るため、ト書きのまま残しています。オーナーが決めたあとで本文にします(追跡: #219)。

- 読み手が持って来るもの: 使う AI(チャット、またはコーディングエージェント)
- このページが渡すもの: 渡す資料(`llms.txt` か `llms-full.txt`)の場所と、渡し方(URL を貼る、ファイルを取り込む)。「できないこと・まだ使えないもの」も渡すこと
- 読み手がすること: 資料を AI に渡す
- できた?: AI が「FloatSoda の資料を読んだ」と答えた、または資料の内容を要約できた
- 次へ進む先: 手順2
- 【未決】コーディングエージェントとチャットで、渡し方を分けて書くか

<details>
<summary>仮に書いた本文(判断の材料。採用は未定)</summary>

FloatSoda の公開サイトは、AI 向けに2つのファイルを配信しています。AI には、このどちらかを渡します。

| ファイル | 中身 | 向く場面 |
| :-- | :-- | :-- |
| `llms.txt` (<https://floatsoda.sumx21t.com/llms.txt>) | 索引 | AI が自分でページを開ける(コーディングエージェントなど) |
| `llms-full.txt` (<https://floatsoda.sumx21t.com/llms-full.txt>) | 全文 | チャットに貼る、またはファイルとして取り込む |

渡し方は、URL を貼るか、ファイルを取り込みます。あわせて、リファレンスの[できないこと・まだ使えないもの](../../reference/limitations.md)を読むように伝えてください。作例の README にも、ウィジェットごとの使い方と「Flutterとの違い」があります。AI が部品を迷うときは、`samples/` の該当する作例の `README.md` を渡せます。

**できた?** AI が「FloatSoda の資料を読んだ」と答えた、または資料の内容を要約できた。

</details>

## 手順2: 作りたいものを頼む

作りたいものを、次の3つを入れて頼む。

- 何を出すか(例: 現在の時刻、表情を切り替えるボタン)
- どこに置くか(ダッシュボード、ワールド座標に固定、コントローラーに追従)
- 押す操作が要るか

押す操作が要る画面は、ダッシュボードに置くよう伝えてください。ワールド座標固定と追従のオーバーレイは、ポインタで押せません(追跡: #182)。

頼み方の例です。

```text
FloatSoda の資料を読んだうえで、SteamVR のダッシュボードに、現在の時刻を毎秒更新して出す
オーバーレイを作ってください。押す操作は要りません。定期更新と SetState の呼び出し条件は、
資料で確かめてください。資料にない API は推測せず、確認が必要な点を示してください。
Program.cs 全体を、そのまま貼れる形で出してください。
```

**できた?** コードが `Program.cs` に貼れる形で返ってきた。

## 手順3: ビルドする

返ってきたコードを `Program.cs` に貼り、次を実行する。

```powershell
dotnet build
```

エラーが出たら、エラーの文をそのまま AI に貼って、直させてください。存在しない名前を AI が書いたときは、ここでコンパイルエラーになります。

**できた?** 「ビルドに成功しました」と出た。

<details>
<summary>できなかったら</summary>

AI に何度か直させても消えないエラーは、[エラーを読んで直す](../5-troubleshoot/read-errors.md)を読んでください。`using` のエラーが出るときは、参照している FloatSoda の版と、`using` の綴りを確かめてください。FloatSoda は、リリースで名前空間を移すことがあります。たとえば、`Text` と `RichText` は 0.4.0 で `FloatSoda.Widgets.Components` から `FloatSoda.Widgets` に移りました。AI が古い `using` を書いている可能性があります。

</details>

## 手順4: 動かす

SteamVR を起動してから、次を実行する。

```powershell
dotnet run
```

SteamVR のダッシュボードを開く。

**できた?** ダッシュボードに、頼んだとおりに動くオーバーレイが出た。

<details>
<summary>できなかったら</summary>

アプリが終了する、例外が出るときは、[エラーを読んで直す](../5-troubleshoot/read-errors.md)を読んでください。起動しているのに出ない、押しても反応しないときは、[反応しないときに切り分ける](../5-troubleshoot/not-responding.md)を読んでください。

</details>

## 手順5: 点検する

> 【未決】この節は判断が要るため、ト書きのまま残しています。オーナーが決めたあとで本文にします(追跡: #219)。

- 読み手が持って来るもの: 動いたコード
- このページが渡すもの: 点検のチェックリスト(FloatSoda で起きやすい食い違い)。各項目は、読み手がコードの中の語を検索して確かめられる形にする
- 読み手がすること: チェックリストの語をコードで検索する。見つかったら、AI に直させる
- できた?: チェックリストのどの語もコードにない
- できなかったら: 見つかった語ごとに、直し方の行き先(「できないこと・まだ使えないもの」、「Flutter の読み替え表」)
- 次へ進む先: チュートリアルが未了なら「最初のオーバーレイを作る」。動いたら「4. 作る」
- 【未決】チェックリストを、このページに持つか、別のリファレンスに持つか。「規約は1か所にだけ書く」ため、制約の内容は「できないこと」を正本にして、ここは語の一覧だけにする案

<details>
<summary>仮に書いた本文(判断の材料。採用は未定)</summary>

動いたコードでも、FloatSoda で起きやすい食い違いが残っていることがあります。次の語を、コードの中で検索してください。見つかったら、見つかった語の行の「直し方」を AI に伝えて、直させます。

| 検索する語 | 起きること | AI への指示の例 |
| :-- | :-- | :-- |
| `Button` | `Button` などの UI コンポーネントは提供していない | `Button` を使わず、`GestureDetector` で組み立てて |
| `WorldSpaceWindow` または `DeviceTrackedWindow` の中の `GestureDetector` | 押しても `OnTap` が呼ばれない | 押す画面は `DashboardWindow` に置いて |
| `ListView`、`GridView`、`SingleChildScrollView` | 公開されていない。使えない | スクロールを使わず、`Stack` と `Positioned` で並べて |
| `ClipRRect`、`ClipPath` | FloatSoda では名前が違う | `ClipRRect` は `ClipRoundRect`、`ClipPath` は `ClipCustomPath` にして |
| `MouseRegion` | FloatSoda では名前が違う | `MouseRegion` は `PointerRegion` にして |
| `margin`、`spacing:` | `Container` に `margin` はなく、`Row` や `Column` に `spacing` はない | `Padding` と `SizedBox` で余白と間隔を作って |
| `SetState` を呼ぶ `Task.Run` や `Timer` の中身 | 別のスレッドから呼ぶと、画面の更新が失われる、またはクラッシュする | `SetState` は、メインスレッドへ戻してから呼んで |

`Size` を指定していないウィンドウは、中身の大きさが変わっても、表示が最初の大きさのまま更新されません。中身の大きさが変わる画面は、`DashboardWindow` に `Size` を指定するよう AI に伝えてください。(追跡: #285)

この表は語の一覧だけで、制約の詳しい内容は[できないこと・まだ使えないもの](../../reference/limitations.md)、Flutter の名前の違いは[Flutter の読み替え表](../../reference/flutter-mapping.md)にあります。

**できた?** 表のどの語もコードにない。

<details>
<summary>できなかったら</summary>

見つかった語は、表の指示を AI に渡して直させ、手順3に戻ってください。直し方の根拠は、上の2つのリファレンスにあります。

</details>
