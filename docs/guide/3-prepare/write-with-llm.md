# AI に FloatSoda を書かせる

> このページは執筆前の骨組みです。設計シートとト書きだけを置き、本文はまだ書いていません(追跡: #219)。

## 設計シート

- 分類: 説明型(Diátaxis: how-to)
- 読み手: だれが / コードをほとんど書かず、AI(Claude、ChatGPT、Codex など)に書かせて VR のツールを作りたい人 / 何を知っている / AI に頼んで動くものを作った経験が少しある。C# と FloatSoda は知らない / 読んで何をしたい / AI に FloatSoda の正しいコードを書かせ、書かれたコードが FloatSoda の作法に合っているかを自分で点検したい
  - 共通の性質と専門用語の扱い: CONTRIBUTING.md の「ドキュメントのトンマナ」の「読み手」
- 出力言語と文体の指定: 日本語。敬体。トンマナは CONTRIBUTING.md の「ドキュメントのトンマナ」に従う
- テーマ: AI に FloatSoda の資料を渡してコードを書かせ、出来上がったコードを点検する手順
- 依頼の解釈: 「点検」を、コードを読まなくてもできる確かめ(ビルド、実行、チェックリスト)に限る。OSC など、FloatSoda の外の通信の書き方は、このページに書かず、AI に聞く前提とする
- テーマファイル: how-to
- Why(目的): AI が「Flutter の知識で書いた、動かないコード」を出す事故を、渡す資料と点検で減らす
- What(目標・結果): AI に渡す資料と頼み方が決まり、出来上がったコードを5つの点検で確かめられる。ビルドが通り、オーバーレイが出る
- How(手段): 手順を、資料を渡す、頼む、ビルドする、動かす、点検するの5つにし、各手順に成功したときの結果を添える。点検は、チェックリスト(FloatSoda で起きやすい食い違い)にする
- 要素:
  - 公開サイトは AI 向けに `llms.txt`(索引)と `llms-full.txt`(全文)を配信している。AI には、このどちらかを渡す(README.md の「ドキュメント」)
  - API リファレンスは、`llms.txt` と検索に取り込む。`llms.txt` が大きくなるため、API は別のファイルに分ける(docs 再編の決定、2026-10-16〜17)。※要確認: 実際の配信形(別ファイル名)
  - FloatSoda の docs と API は、AI が誤用しにくいことを目標に設計してある(AGENTS.md の「Target Users」の1番目)
  - 作例の README は、ウィジェットごとに使い方と「Flutterとの違い」を書いている。AI にはこの README も渡せる(`samples/FloatSoda.Samples.Flex/README.md`)
  - 点検の項目: `Button` などの UI コンポーネントを使っていないか(未提供)、`WorldSpaceWindow` か `DeviceTrackedWindow` に `GestureDetector` を置いていないか(コールバックが呼ばれない)、`Size` を省略したウィンドウの中身が増減しないか、バックグラウンドスレッドから `SetState` を呼んでいないか、`ListView` などのスクロール部品を使っていないか(AGENTS.md の「Widget/Element Tree」、CHANGELOG.md の「Known issues」)
  - 点検の項目(Flutter 由来の食い違い): `ClipRRect`、`MouseRegion`、`margin`、`spacing` など、FloatSoda にない名前や引数がないか(各作例の README の「Flutterとの違い」)
  - 点検の方法: ビルドが通るか(存在しない名前はコンパイルエラーになる)、実行して画面が出るか、押して反応するか。コードを読めない人でもできる確かめにする
  - OSC など外の通信は、AI に任せる。FloatSoda 本体は OSC に依存していない(docs 再編の決定、2026-10-16〜17)
  - FloatSoda の名前空間は、リリースで移ることがある。0.4.0 では `Text`、`RichText`、`ImageProvider` などが移った。AI が古い `using` を書くことがある(CHANGELOG.md の 0.4.0 の Changed)
- 見出し:
  - この手順でできること
  - 手順1: AI に資料を渡す
  - 手順2: 作りたいものを頼む
  - 手順3: ビルドする
  - 手順4: 動かす
  - 手順5: 点検する
  - 点検に落ちたとき
- ※要確認:
  - `llms.txt` と `llms-full.txt` の中身が、AI が書くのに足りるか(ジュニアコーダーテストで確かめる)
  - API リファレンスを取り込んだあとの `llms.txt` の構成
  - 頼み方のひな形(プロンプト)を載せてよいか、載せるならどの AI で通したか(通していないひな形は載せない)

## ト書き

### この手順でできること

- 読み手が持って来るもの: 「AI に作らせたい」という目的
- このページが渡すもの: 5つの手順の予告と、終わったときの状態(AI が書いたコードでオーバーレイが出る)
- 読み手がすること: 手順の流れをつかむ
- 次へ進む先: 手順1

### 手順1: AI に資料を渡す

- 読み手が持って来るもの: 使う AI(チャット、またはコーディングエージェント)
- このページが渡すもの: 渡す資料(`llms.txt` か `llms-full.txt`)の場所と、渡し方(URL を貼る、ファイルを取り込む)。「できないこと・まだ使えないもの」も渡すこと
- 読み手がすること: 資料を AI に渡す
- できた?: AI が「FloatSoda の資料を読んだ」と答えた、または資料の内容を要約できた
- 次へ進む先: 手順2
- 【未決】コーディングエージェントとチャットで、渡し方を分けて書くか

### 手順2: 作りたいものを頼む

- 読み手が持って来るもの: 作りたいもの(例: 時刻を出す、表情を切り替える)
- このページが渡すもの: 頼み方の型(作りたいもの、置き場所、押す操作の有無)。置き場所によって押せない制約があること
- 読み手がすること: AI に頼み、コードを受け取る
- できた?: コードが `Program.cs` に貼れる形で返ってきた
- 次へ進む先: 手順3

### 手順3: ビルドする

- 読み手が持って来るもの: AI のコード
- このページが渡すもの: `dotnet build` の1コマンド。エラーが出たら、そのまま AI に貼って直させること
- 読み手がすること: ビルドして、エラーを AI に渡す
- できた?: ビルドに成功した
- できなかったら: 直らないエラー → ガイドの「エラーを読んで直す」
- 次へ進む先: 手順4

### 手順4: 動かす

- 読み手が持って来るもの: ビルドが通ったコード、SteamVR
- このページが渡すもの: SteamVR を起動してから `dotnet run` すること
- 読み手がすること: 実行して画面を見る
- できた?: ダッシュボードにオーバーレイが出た
- できなかったら: 出ない → ガイドの「エラーを読んで直す」、「反応しないときに切り分ける」
- 次へ進む先: 手順5

### 手順5: 点検する

- 読み手が持って来るもの: 動いたコード
- このページが渡すもの: 点検のチェックリスト(FloatSoda で起きやすい食い違い)。各項目は、読み手がコードの中の語を検索して確かめられる形にする
- 読み手がすること: チェックリストの語をコードで検索する。見つかったら、AI に直させる
- できた?: チェックリストのどの語もコードにない
- できなかったら: 見つかった語ごとに、直し方の行き先(「できないこと・まだ使えないもの」、「Flutter の読み替え表」)
- 次へ進む先: チュートリアルが未了なら「最初のオーバーレイを作る」。動いたら「4. 作る」
- 【未決】チェックリストを、このページに持つか、別のリファレンスに持つか。「規約は1か所にだけ書く」ため、制約の内容は「できないこと」を正本にして、ここは語の一覧だけにする案

### 点検に落ちたとき

- 読み手が持って来るもの: 点検で見つかった語
- このページが渡すもの: 語ごとの直し方の指示文の例(AI に渡す1文)と、行き先
- 読み手がすること: 指示文を AI に渡して直させ、手順3から繰り返す
- 止まる箇所: なし。ここでページは終わる
