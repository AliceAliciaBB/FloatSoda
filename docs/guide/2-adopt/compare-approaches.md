- 分類: 説明型(Diátaxis: explanation)

- How(手段): 比べる軸を決め、軸ごとに「uGUI で作る」「OpenVR を直接呼ぶ」「FloatSoda」を並べる。評価語を使わず、違いの事実と、引き受ける負担を書く
- 要素:
  - FloatSoda では、UI がすべて C# のコードで、シーンもプレハブもない。diff、レビュー、grep、AI の生成がコードにそのまま使える(AGENTS.md の「Target Users」)
  - uGUI は、シーンとプレハブの YAML、GUID 参照で UI を持つ。この形式は diff が読みにくく、AI が生成しにくい、というのが FloatSoda の想定読者の困りごとである(AGENTS.md の「Target Users」の3番目)
  - FloatSoda は Unity のランタイムに依存せず、.NET と SkiaSharp と OpenVR で完結する(再編前の `docs/TargetUsers.md`)
  - OpenVR を直接呼ぶ作り方では、ウィジェット層を使わず `FloatSoda.OVR` の API だけでオーバーレイを出せる。描画する画像は自分で用意する(`samples/FloatSoda.Samples.PrimitiveOverlay/Program.cs` は PNG をテクスチャにしている)
  - FloatSoda は、レイアウト、描画、ポインタ入力、差分更新を肩代わりする。オーバーレイの置き場所は、ウィンドウの種類を選ぶだけで切り替わる(README.md の「特徴」)
  - 状態の書き方は、オブジェクトを置いて書き換える(uGUI)のではなく、状態を変えて UI を作り直す(`SetState`)形である(再編前の `docs/TargetUsers.md`)
  - FloatSoda にできないこと、まだないことは、リファレンスの「できないこと・まだ使えないもの」に集めている(docs 再編の決定、2026-10-16〜17)
  - 比べる軸の候補(エージェントの案): 作る手間、変更の追いやすさ(diff・レビュー)、AI が書けるか、置き場所の選択、配る手間、できること、開発の安定度

### 比べる3つの作り方

- 読み手が持って来るもの: 「uGUI で作れるのでは」「OpenVR を直接叩けば」という疑問
- このページが渡すもの: 3つの作り方の1行の説明と、比べる軸の一覧
- 読み手がすること: 自分が重く見る軸を選ぶ
- 次へ進む先: 軸の各節

### 作る手間

- 読み手が持って来るもの: 画面を作る手間への関心
- このページが渡すもの: 3つの作り方で、同じ画面(数字とボタン)を作るときの手間の違いの表。FloatSoda の側は、チュートリアルのコードの量を示す
- 読み手がすること: 自分の作りたい画面の手間を見積もる
- 次へ進む先: 「変更の追いやすさと、AI の書きやすさ」
- 【未決】uGUI 側の手間を、一次情報なしで書くか。書けないなら、この軸は FloatSoda と OpenVR 直接の2つに絞る

### 変更の追いやすさと、AI の書きやすさ

- 読み手が持って来るもの: UI の変更をレビューしたい、AI に書かせたい
- このページが渡すもの: UI がコードだけであることの意味(diff、レビュー、検索、生成)と、そうならない作り方(シーンとプレハブ)との違い
- 読み手がすること: 自分の開発の形(1人、チーム、AI 任せ)と照らす
- 次へ進む先: 「置き場所と入力」。AI に書かせる手順は、ガイドの「AI に FloatSoda を書かせる」

- 読み手がすること: 自分の置き場所と押す必要を、制約と照らす
