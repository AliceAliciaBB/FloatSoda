## 設計シート

- 分類: 説明型(Diátaxis: how-to)
- 読み手: だれが / 提案が通って、決定を記録に残したい人。Flutter との差異を残したい人を含む / 何を知っている / 提案の議論の結果。ADR という言葉は知らなくてよい / 読んで何をしたい / 決定を、あとから「なぜそう決めたか」を読める形で ADR に書く
- 出力言語と文体の指定: 日本語。敬体(CONTRIBUTING.md の「ドキュメントのトンマナ」の「文体」)
- テーマ: 決定を ADR(Architecture Decision Record)として、背景・決定・理由・影響の順に書き、置き場所に追加する
- 依頼の解釈: ADR の移行(既存の決定の記録を repo に移すこと)ではなく、新しい決定を書く手順と読む
- テーマファイル: how-to(書く対象の文書の型は decision)
- Why(目的): 決定の理由が議論のコメントにしかないと、あとから「なぜこうなっているか」を追えず、同じ議論を繰り返す。決定を ADR に残して、設計の理由を読めるようにする
- What(目標・結果): ADR が1本、決められた置き場所にある。背景、決定、理由、影響が書かれている。Flutter との差異なら、差異の5項目も書かれている
- How(手段): 書くべき決定かを確かめる → 番号と置き場所を決める → 書く → 差異なら5項目を足す → PR で出す

## ト書き

### この手順でできること

- 読み手が持って来るもの: 議論で決まった内容
- このページが渡すもの: 手順が終わったときの状態(ADR が1本、置き場所にある)と、ADR が「なぜそう決めたか」に答えるものであること
- 読み手がすること: 自分の決定がこのページの対象かを確かめる
- 次へ進む先: 「前提条件」

### 前提条件

- 読み手が持って来るもの: 決まった内容と、議論の Issue
- このページが渡すもの: 提案の書き方(../6-propose/write-proposal.md)、規約(../3-prepare/conventions.md)
- 読み手がすること: 足りなければ先に読む
- 次へ進む先: 手順1

### 手順1: ADR に書く決定かを確かめる

- 読み手が持って来るもの: 決まった内容
- このページが渡すもの: ADR に書くものの目安。設計判断、依存やプロジェクト構成の決定、Flutter との差異、public API の方針。typo の修正のような設計判断のない変更は書かない(CONTRIBUTING.md の「Issue が必須な変更」と同じ線)
- 読み手がすること: 書くかどうかを決める
- できた?: 「書く」「書かない」のどちらかを、理由とあわせて言える
- 次へ進む先: 書くなら手順2

### 手順2: 番号と置き場所を決める

- 読み手が持って来るもの: 書くと決めた決定
- このページが渡すもの: 置き場所と番号の付け方
- 読み手がすること: 番号を決め、ファイルを作る
- 【未決】置き場所と番号の付け方。決まるまで、このページは「決まっていない」とだけ書き、手順を埋めない(後回しの決定、docs 再編の決定、2026-10-17)
- 次へ進む先: 手順3

### 手順3: 背景・決定・理由・影響を書く

- 読み手が持って来るもの: 議論の記録
- このページが渡すもの: 4つの欄に何を書くか。背景は決める前の状況、決定は選んだもの、理由は選ばなかった案と選んだ理由、影響は決めたことで生じる制約や代償
- 読み手がすること: 4つの欄を埋める
- できた?: 理由の欄に、選ばなかった案が少なくとも1つ書かれている
- 次へ進む先: 手順4(差異の場合)、そうでなければ手順5

### 手順4: Flutter との差異なら、5項目を足す

- 読み手が持って来るもの: Flutter と違う設計の決定
- このページが渡すもの: 記録必須の5項目と、ADR の欄との対応。差異を固定するテストの名前を書くこと。利用者に見える差異は、利用者向けの docs にも書くこと
- 読み手がすること: 5項目を ADR に書く
- できた?: 5項目がすべて埋まり、テストが実在する
- 止まる箇所: 台帳(`known-divergences.md`)にすでに同じ差異のエントリがあるとき。重複させず、どちらを正にするかをオーナーに確かめる(移行は後回し)
- 次へ進む先: 手順5

### 手順5: PR で出す

- 読み手が持って来るもの: 書いた ADR
- このページが渡すもの: PR の範囲(ADR の追加だけにする)と、関連する Issue への結び付け(`Closes #NN`)
- 読み手がすること: PR を出す
- 次へ進む先: レビュー(../5-submit/address-review.md)

### ADR を読むとき

- 読み手が持って来るもの: 「なぜこう作ったのか」という疑問
- このページが渡すもの: ADR の読み方(4つの欄の見方)と、決定の一覧(リファレンス)への案内
- 読み手がすること: 該当する ADR を探す
- 【未決】一覧のページの置き場所。書き方のページと、一覧のページを分ける(docs 再編の決定、2026-10-16〜17)

### うまくいかないとき

- 読み手が持って来るもの: 書けない、または何が決定か分からない状況
- このページが渡すもの: 症状ごとの行き先。決定が決まっていない → 提案を書くページ(../6-propose/write-proposal.md)に戻る
- 読み手がすること: 該当する行き先に戻る
- 止まる箇所: なし
