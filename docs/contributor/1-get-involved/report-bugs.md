# 不具合を切り分けて報告する

> このページは執筆前の骨組みです。設計シートとト書きだけを置き、本文はまだ書いていません(追跡: #219)。

## 設計シート

- 分類: 説明型(Diátaxis: how-to)
- 読み手: だれが / 自分のツールで FloatSoda を使っていて、おかしな挙動に出会った人。動作検証をしていて「落ちた / 落ちなかった」を報告したい人 / 何を知っている / 自分のコードと、`dotnet run` で動かす手順。FloatSoda の内部は知らなくてよい / 読んで何をしたい / 踏んだ不具合が FloatSoda 側の問題かを確かめ、Issue として報告したい
- 出力言語と文体の指定: 日本語。敬体(CONTRIBUTING.md の「ドキュメントのトンマナ」の「文体」)
- テーマ: 不具合を最小の再現に絞り、FloatSoda 側の問題かを切り分けて、Issue に報告する
- 依頼の解釈: なし
- テーマファイル: how-to
- Why(目的): 切り分けないまま報告すると、FloatSoda の問題か、使い方か、環境かが分からず、直す人が再現に時間を使う。報告の形をそろえて、直る早さを上げる
- What(目標・結果): Issue が1件立っている。概要、最小の再現、期待した挙動と実際の挙動、バージョンと環境が書かれている
- How(手段): 利用者向けの切り分けを済ませる → 最小の再現に絞る → Flutter の挙動と比べる(Flutter 由来の場合) → 環境を集める → Issue のテンプレートに書いて出す
- 要素:
  - 報告には Issue のバグ報告テンプレートを使う(CONTRIBUTING.md の「ブランチ・PRフロー」、`.github/ISSUE_TEMPLATE/bug_report.yml`)
  - テンプレートの必須欄は、バグの概要、最小再現コードまたは再現手順、期待した挙動、実際の挙動、FloatSoda のバージョン、.NET SDK のバージョン、OS(`.github/ISSUE_TEMPLATE/bug_report.yml`)
  - 表示や描画の問題では、GPU とドライバ、HMD、SteamVR のバージョンを書く(`.github/ISSUE_TEMPLATE/bug_report.yml` の「描画・VR 環境」)
  - Flutter 由来の Widget に関する不具合では、Flutter でも同じことが起きるかを書く。任意の欄(`.github/ISSUE_TEMPLATE/bug_report.yml` の「Flutter との対応」)
  - Issue のタイトルには、何をする Issue かを書く。種別や領域はラベルで表し、`feat(Widget):` のような prefix は付けない(CONTRIBUTING.md の「タイトルとラベル」)
  - 動作検証の報告は「落ちた / 落ちなかった」と環境を書く。落ちなかった報告も、その環境で動いた記録になる(docs 再編の決定、2026-10-16〜17)
  - 実機でのチェックの記録は、HMD・GPU・プラットフォーム・モード・日付を名前に含む jsonl に残している(`.agents/skills/floatsoda-device-test-run/SKILL.md`)
  - 利用者側の切り分けは、利用者向けのガイドの「反応しないときに切り分ける」と「利用者の環境で動かないとき」にある(docs 再編の決定、2026-10-16〜17)
- 見出し:
  - この手順でできること
  - 前提条件
  - 手順1: 利用者向けの切り分けを済ませる
  - 手順2: 最小の再現に絞る
  - 手順3: Flutter でも起きるかを確かめる(Flutter 由来の場合)
  - 手順4: バージョンと環境を集める
  - 手順5: Issue を出す
  - 動作検証の結果を報告する場合
  - うまくいかないとき
- ※要確認:
  - 最小の再現に絞る具体的な手順(ウィジェットツリーをどこまで削るかの目安)を示す一次情報があるか。なければ書かない
  - 再現しない報告でも Issue を出してよいか(オーナーの方針)
  - 利用者向けの該当ページ(not-responding.md、user-environment-issues.md)が、ここで想定する切り分けの内容を持つか(両ページとも未執筆)

## ト書き

### この手順でできること

- 読み手が持って来るもの: 「おかしな挙動を踏んだ」という状況だけ
- このページが渡すもの: 手順が終わったときの状態(必須の欄が埋まった Issue が1件ある)と、手順の数
- 読み手がすること: 自分の状況がこのページの対象かを確かめる
- 次へ進む先: 「前提条件」

### 前提条件

- 読み手が持って来るもの: 動かなくなったコードと、手元の環境
- このページが渡すもの: GitHub のアカウント、FloatSoda のバージョンが分かること、再現できるコードか手順があること
- 読み手がすること: 足りないものを用意する
- 止まる箇所: 再現できない場合。※要確認(再現しない報告を受け付けるか)
- 次へ進む先: 手順1

### 手順1: 利用者向けの切り分けを済ませる

- 読み手が持って来るもの: 動かない症状
- このページが渡すもの: 利用者向けの「反応しないときに切り分ける」(../../guide/5-troubleshoot/not-responding.md)と「利用者の環境で動かないとき」(../../guide/7-maintain/user-environment-issues.md)へのリンク
- 読み手がすること: リンク先の切り分けを先に行い、使い方や環境の問題ではないことを確かめる
- できた?: 使い方の誤りや環境の問題では説明がつかない
- 次へ進む先: 手順2

### 手順2: 最小の再現に絞る

- 読み手が持って来るもの: 不具合が出るコード
- このページが渡すもの: 再現に関係しない部分を外していく考え方と、Issue テンプレートの「最小再現コード」の例
- 読み手がすること: ウィジェットツリーを小さくして、それでも起きるコードを残す
- できた?: 貼り付けるだけで動くコードで、不具合が再現する
- 次へ進む先: 手順3(Flutter 由来のウィジェットの場合)、そうでなければ手順4

### 手順3: Flutter でも起きるかを確かめる(Flutter 由来の場合)

- 読み手が持って来るもの: 最小の再現コード
- このページが渡すもの: Flutter でも同じことが起きるかを確かめる目的(FloatSoda のバグ、Flutter の仕様、意図した差異の3つを分ける)。Flutter の元の実装を引く手順は、開発環境のページ(../3-prepare/dev-environment.md)へリンクする
- 読み手がすること: 分かる範囲で確かめる。分からなければ空欄にしてよい(欄は任意)
- 次へ進む先: 手順4

### 手順4: バージョンと環境を集める

- 読み手が持って来るもの: 手元の環境
- このページが渡すもの: 集める値の一覧(FloatSoda のバージョン、`dotnet --version` の出力、OS、表示の問題なら GPU・HMD・SteamVR)と、それぞれの調べ方
- 読み手がすること: 値を書き出す
- 次へ進む先: 手順5

### 手順5: Issue を出す

- 読み手が持って来るもの: 再現コードと環境の値
- このページが渡すもの: バグ報告テンプレートへのリンクと、欄ごとに何を書くかの対応
- 読み手がすること: テンプレートを開き、欄を埋めて出す
- できた?: Issue が立ち、`bug` のラベルが付いている
- 止まる箇所: Issue は公開される。出す前に、パスや個人情報が貼り付けに入っていないかを確かめる
- 次へ進む先: 自分で直したい場合は、ブランチ名と PR の範囲(../3-prepare/conventions.md)

### 動作検証の結果を報告する場合

- 読み手が持って来るもの: 実機で試した結果
- このページが渡すもの: 「落ちた / 落ちなかった」と環境(HMD、GPU、プラットフォーム、モード、日付)を書く形。落ちなかった報告も記録になること
- 読み手がすること: 結果と環境を、同じ形で書く
- 【未決】報告の置き場所を Issue にするか、サンプルの `checks/results/` にするか

### うまくいかないとき

- 読み手が持って来るもの: 手順で詰まった状況
- このページが渡すもの: 再現できない場合と、FloatSoda の問題か判断できない場合の行き先
- 読み手がすること: 該当する行き先を選ぶ
- 止まる箇所: なし
